# Career CV v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a verified two-page Senior Backend/Platform master CV, a one-page comparison, immutable local snapshots and a consistent Experience page from one public evidence source.

**Architecture:** Extend `content/cv/master.json` with stable, public-safe achievement records and hydrate role highlights through shared helpers. Keep variant selection declarative, extend the existing LaTeX generator for projects and expected page counts, and add an ignored no-overwrite snapshot command. The website and Markdown exports consume the same hydrated career data.

**Tech Stack:** Node.js, JSON Schema/Ajv, Gatsby/React, LaTeX, Tectonic, Node test runner, Poppler.

**Spec:** `docs/superpowers/specs/2026-10-10-career-cv-v2-design.md`

## Global Constraints

- Use British English and public-safe wording only.
- Preserve production, UAT, load-test and not-production qualifiers exactly.
- Do not commit raw screenshots, private contact data, generated PDFs or generated LaTeX.
- Reuse the existing variant-driven LaTeX architecture and A4 visual language.
- `master-v2` must compile to exactly two pages; `swe` must compile to exactly one page.
- Do not merge, deploy, publish the website or submit applications.

## Review Focus

- A variant referencing an unknown or unconfirmed achievement must fail validation.
- Hydration must not duplicate or reorder legacy role highlights unexpectedly.
- LaTeX escaping must preserve percentages, ampersands and public URLs.
- Snapshot creation must reject an existing destination without changing it.
- A successful compiler exit with the wrong page count must still fail.
